Setup Guide

Run the API, admin console, worker, database, cache and encrypted-file store locally. Organization login needs an identity provider.

Covers the local Docker Compose environment. It is not a production deployment recipe.

On this page

Prerequisites

  • Docker Desktop with Docker Compose v2
  • Node.js 24 and pnpm 11.25.0 for extension builds and owner provisioning
  • The EPV repository checked out locally

Start the Docker stack

From the repository root, start the services:

Terminal
docker compose up -d

Compose starts PostgreSQL, Redis, RustFS, the API, the admin console, the policy worker, and this site. Migrations and object-store initialization run as one-shot services.

Keep local services local

The development credentials and single-host RustFS volume are for local use. Do not expose this stack to the public internet or use it for production secrets.

Open local services

This site
http://localhost:8090
Organization console
http://localhost:8080

http://localhost:3000/health/ready
Invitation email preview
http://localhost:18025 (Mailpit profile)

The admin console can display its locked state before OIDC is configured. That is expected; there is no default organization username or password.

Build the extension

Install workspace dependencies, then build the Chromium extension:

Repository root
pnpm install --frozen-lockfile
pnpm --filter @epv/extension build

Load apps/extension/.output/chrome-mv3 from brave://extensions or chrome://extensions using Developer mode and Load unpacked. See the Extension Download guide.

Configure organization sign-in

EPV uses OIDC Authorization Code with PKCE. Register a public client for the admin console and a separate public client for the extension. Do not create or embed a client secret in either app.

  1. Set the API's OIDC_ISSUER and OIDC_AUDIENCE in .env.
  2. Set VITE_OIDC_ISSUER, VITE_OIDC_AUDIENCE, and VITE_ADMIN_OIDC_CLIENT_ID for the admin console build. Set VITE_OIDC_CLIENT_ID, the same issuer/audience, and VITE_API_BASE_URL before building the extension.
  3. Allow the exact local console callback http://localhost:8080/ at the identity provider. For the extension, allow the redirect from chrome.identity.getRedirectURL().
  4. Set CORS_ALLOWED_ORIGINS for the console and installed chrome-extension://<extension-id> origin.
  5. Rebuild the admin image and extension after changing their Vite build settings.
OIDC values are public client settings

Issuer, audience, and client IDs are identifiers. Never place an IdP client secret, signing private key, or database password in a Vite variable.

Provision the first owner

After the IdP is configured, sign in once and use the verified identity provider subject (sub) for the first owner membership:

Repository root
pnpm --filter @epv/api provision:member -- \
  --issuer <issuer-url> \
  --subject <oidc-subject> \
  --organization <organization-name> \
  --role owner

This command uses the administrative migration database connection. The API itself uses a restricted application database role. Do not share the admin database password.

Troubleshooting

“Sign in with your organization” is disabled

The admin web image was built without its public OIDC settings. Configure VITE_OIDC_ISSUER, VITE_ADMIN_OIDC_CLIENT_ID, and VITE_OIDC_AUDIENCE, then rebuild admin-web.

The extension can create a vault but cannot connect

Local vault operation does not need OIDC. For sync, verify API issuer/audience settings, extension Vite settings, exact redirect URI, CORS origin, and owner membership.

The API readiness check fails

Run docker compose ps and confirm PostgreSQL and Redis are healthy. Then inspect service logs with docker compose logs api postgres redis.

Encrypted file upload fails locally

Confirm RustFS is healthy and the one-shot bucket initialization service completed. The API uses the internal rustfs:9000 endpoint.

Use the GHCR Compose images

The published deployment is a Compose bundle of separate app images and infrastructure containers. Log in to GHCR first if the packages are private, then choose the same image tag for all EPV services:

Terminal
docker compose -f docker-compose.yml -f docker-compose.ghcr.yml pull
docker compose -f docker-compose.yml -f docker-compose.ghcr.yml up -d --no-build

Set EPV_IMAGE_TAG to the version published by the repository workflow. Review .env.example and docs/production-deployment.md in the repository before using a non-local host.
